# NKS-012
# Context Modality Resolution

**Document ID:** NKS-012  
**Title:** Розв’язання деонтичної модальності з контексту  
**Status:** Draft  
**Version:** 0.1  
**Depends on:** NKS-000, NKS-011  
**Related:** VerbRegistry, Inference Engine, TraceStep

---

## 1. Призначення

Цей документ визначає шар між **впізнаванням дії** (matcher + NormVerb Registry) і **підсумковим вердиктом**.

| Шар | Відповідає на |
|-----|----------------|
| NKS-011 / matcher | *Яка дія?* (lemma) |
| **NKS-012 / context scanner** | *Який режим у цій конструкції?* (OBL / PERM / PROH / POW / …) |

**Принцип:** контекст речення має пріоритет над типовою `modality` з реєстру.  
Реєстр описує **оператор дії**, не єдине джерело деонтичного режиму.

---

## 2. Потік обчислення


\* Root-match — лише за жорсткими правилами; при сумніві → OOV, не «впевнена» дія.

---

## 3. Джерела модальності (`modality_source`)

| Значення | Коли |
|----------|------|
| `context` | Є явний маркер без конфлікту і без заперечення в scope |
| `registry` | Маркерів немає → типова modality з реєстру |
| `conflict_default` | Кілька несумісних маркерів → консервативний вибір |
| `negation_scope` | Маркер під запереченням → не тихий автовердикт; потрібна людина |

У Trace MUST бути видно `modality_source`.

---

## 4. Таблиця маркерів (дані, не хардкод)

Файл: `data/context_markers_uk.json` (або .yaml).

Містить щонайменше:
- списки маркерів → OBL / PERM / PROH
- токени заперечення (`не`, `без`, …)
- порядок пріоритету при конфлікті: **PROH > OBL > PERM**

Зміна маркерів = зміна **даних** + версія файлу, не обов’язково зміна коду.

---

## 5. Пріоритет


**Картки пакету норм МСУ (NKS / packages) НЕ змінюють** `final_modality` у Demo.

---

## 6. Scope заперечення

- Шукати заперечення **лише у вузькому вікні** безпосередньо перед маркером (орієнтир: 1–4 токени).
- НЕ сканувати всю попередню частину документа/клаузи без обмеження.
- Приклад: «не має права» → `negation_scope`.  
  «не проводила … тому має право» → далеке «не» НЕ гасить «має право».

Поведінка Demo при `negation_scope`:
- не видавати тихий PERM/OBL з цього маркера;
- позначити в Trace потребу ручної перевірки.

---

## 7. Межа конструкції (не «будь-яка кома»)

### 7.1. Одна модальна зона (НЕ різати)

Однорідні дії під **спільним** маркером:

> «Секретар **зобов'язаний** скласти протокол, підписати його **та** надати копії»

→ OBL поширюється на *скласти / підписати / надати*.

Роздільники `,` / `та` у переліку **не** починають нову модальну зону самі по собі.

### 7.2. Нова модальна зона (різати)

Протиставлення / новий режим:

- сполучники на кшталт **а / проте / однак** у ролі протиставлення;
- явний новий суб’єкт із **власним** модальним маркером.

> «Рада ухвалює рішення, **а** секретар **повинен** оприлюднити…»

→ різні зони для різних дієслів.

---

## 8. Root-match (обмеження)

Допустимо лише якщо:
- достатня довжина кореня;
- обмежена схожість (напр. Левенштейн ≤ 1–2 або еквівалентний жорсткий критерій);
- у Trace: `match_type: root`, знижений confidence.

**При сумніві: OOV, не підміна lemma.**

Обов’язкові Golden Tests на **хибні** root-збіги, не лише на зниження OOV.

---

## 9. Конфлікт маркерів

Якщо в одній модальній зоні кілька маркерів різних класів:
- застосувати пріоритет PROH > OBL > PERM;
- `modality_source = conflict_default`;
- у Trace: попередження, що вердикт консервативний і потребує перевірки людиною.

---

## 10. Trace (мінімальні поля кроку)

Окрім `label`:
- `step_type` (init | verb_match | modality_resolve | computation | oov | …)
- `matched_verb` / lemma
- `match_type`: lemma | form | root
- `modality`
- `modality_source`

---

## 11. Критерії готовності реалізації

- [ ] Маркери завантажуються з `data/`, не зашиті лише в код
- [ ] Працюють усі чотири `modality_source`
- [ ] Заперечення — вузьке вікно
- [ ] Однорідні переліки не ріжуться помилково по `,`/`та`
- [ ] Конфлікт маркерів видимий у Trace
- [ ] Root не дає «тихої» хибної дії
- [ ] Golden Tests: заперечення; складена конструкція з `а`; хибний root; конфлікт маркерів
- [ ] На еталонному РЕГЛАМЕНТІ: більше коректних влучань тих самих lemma, менше хибних OOV; ріст не за рахунок агресивного root
