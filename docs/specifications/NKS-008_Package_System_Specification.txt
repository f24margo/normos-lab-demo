## 1. Преамбула

Настоящий документ определяет систему пакетов (Package System) — механизм модульности и расширяемости NormOS.

Пакеты — это основной способ расширения функциональности без изменения ядра.

---

## 2. Назначение

Package System позволяет:
- Устанавливать, обновлять и удалять функциональные модули.
- Поддерживать доменные пакеты (МСУ, Корпоративное управление, Техническое регулирование и т.д.).
- Обеспечивать независимость пакетов друг от друга.
- Сохранять совместимость с Конституцией.

---

## 3. Архитектурные императивы

- **Loose Coupling** — пакеты не имеют прямых зависимостей от ядра.
- **Event-Driven** — пакеты взаимодействуют с ядром только через события.
- **Versioning** — каждый пакет имеет версию и зависимости.
- **Isolation** — пакет не может нарушить целостность ядра.

---

## 4. Структура пакета

Пакет NormOS — это директория со следующей структурой:

```
/package-name/
├── manifest.json          # метаданные пакета
├── models/                # NormGene, правила
├── procedures/            # нормативные процедуры
├── handlers/              # обработчики событий
├── tests/
└── README.md
```

---

## 5. Основные события пакетов

- `PackageInstalled`
- `PackageUpdated`
- `PackageRemoved`
- `PackageLoaded`

---

## 6. Manifest (пример)

```json
{
  "name": "local-self-government",
  "version": "0.1.0",
  "requires": ["core >= 0.1"],
  "domain": "msu",
  "norm_genes": 45,
  "author": "..."
}
```

---

## 7. Требования к MVP

**MUST:**
1. Простая система установки пакетов (через manifest).
2. Автоматическая регистрация обработчиков событий при загрузке пакета.
3. Поддержка минимум 2-х доменных пакетов (например, `msu-ukraine` и `corporate`).
4. Проверка совместимости версий.

**SHOULD:**
- Команда `normos package install <name>`.

---

## 8. Соответствие Конституции

- Обеспечивает **расширяемость** без нарушения принципов.
- Поддерживает **независимость теории от реализации**.
