# NormVerb Registry Specification

**Document ID:** NKS-011  
**Title:** NormVerb Registry — методологія відбору, структура, OOV  
**Status:** Draft  
**Version:** 0.1  
**Depends on:** NKS-000, NKS-002

## 1. Призначення

Документ визначає:
1. формування реєстру нормативних глаголів;
2. критерії відбору та повноти;
3. структуру запису;
4. поведінку при Out-Of-Vocabulary (OOV).

Реєстр — емпіричний тест гіпотези про скінченний алфавіт нормативних операторів (монографія, Додаток A).

## 2. Нормативний глагол

Оператор, що змінює нормативний стан і має модальність OBL / PERM / PROH / POW / IMM.

## 3. Методологія відбору

Джерела: Закон про місцеве самоврядування, регламенти рад, протоколи сесій.

Кроки: вилучення → фільтрація → нормалізація до lemma → класифікація modality/category → валідація → фіксація версії.

Ціль v0.2: близько 100 записів (орієнтир, не догма). Повнота = coverage + precision на тестовому корпусі.

## 4. Структура запису

| Поле | Опис |
|------|------|
| id | V001, V002… |
| lemma | інфінітив |
| forms | список словоформ |
| modality | OBL / PERM / PROH / POW / IMM |
| category | процедурний / конститутивний / скасувальний / контрольний |
| typical_agents | Рада, Голова… |
| status | draft / validated |

## 5. Розміщення

data/norm_verbs_uk.yaml (або .json)  
core/verb_registry.py  

Код не містить хардкоду словника.

## 6. OOV (обовʼязково)

1. Не вигадувати вердикт  
2. Повернути «не визначено» / OOV  
3. Записати в data/oov_log.jsonl  
4. (Бажано) запропонувати кандидатів на додавання  

OOV-rate — метрика для протоколу фальсифікації алфавіту.

## 7. Inference і граф

engine.infer() повертає структурований trace.  
Граф Demo будується з trace, не з фіксованих 5 вузлів.
