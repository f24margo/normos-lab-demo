## 1. Філософія

Глагол у нормативно-формалізованій лінгвістиці — це **не лексична одиниця**, а **оператор нормативного переходу**, який перетворює статичний текст закону на динамічну модель дій.

Реєстр NormVerb — це серце NormOS, єдине джерело істини для всіх модулів.

---

## 2. Ключові принципи (згідно з монографією)

### 2.1. Природа нормативного глагола
- Глагол з’єднує **State₁ → State₂**
- Відокремлювати дескриптивні глаголи від нормативних
- Кожен глагол — це потенційний **нормативний перехід**

### 2.2. Функціональна класифікація
- **Процедурні** — фіксують кроки (підписати, зареєструвати)
- **Конститутивні (POW)** — створюють нові норми (призначити, затвердити)
- **Змінювальні/Скасувальні** — припиняють дію (скасувати, припинити)
- **Контрольні** — зобов’язують до перевірки (контролювати, звітувати)

### 2.3. Багата модель даних
Кожен запис повинен містити:
- `verb_id` — унікальний ідентифікатор
- `base_form` — інфінітив
- `modality` — OBL / PERM / PROH / POW
- `transition_type` — state_change / create / terminate / delegate
- `pre_condition` — умови до переходу
- `post_state` — результат переходу
- `consequences` — можливі наслідки
- `frequency` — частотність у документах

---

## 3. Гібридний метод наповнення

1. **Автоматичний етап** — вилучення інфінітивів з корпусу документів
2. **LLM-підтримка** — початкова розмітка
3. **Експертна валідація** — юрист + лінгвіст
4. **Циклічне оновлення** — завантаження нових документів → нові глаголи → валідація

---

## 4. Інтеграція в архітектуру NormOS

- **NormFactory** — парсинг тексту в формальну модель
- **Inference Engine** — обчислення дозволеності переходу
- **NormGraph** — візуалізація мережі переходів
- **NormTransition** — атомарна одиниця динаміки

## 5. План реалізації (4 тижні)

**Тиждень 1** — Стабілізація реестру (100+ глаголів + модальності)  
**Тиждень 2** — Парсер + перевірка відповідності  
**Тиждень 3** — Генерація пропозицій правок  
**Тиждень 4** — Повноцінний демо-прототип
